Basics

1. The pieces

ArenaOS is one system made of a few programs. Each person at the venue uses a different one, but they all read and write the same data. Every customer has one account, one wallet and one bill, across every branch.

☁ Server (API + database)

The brain. It stores everything, runs every session timer, prices everything and signs every command sent to a PC. You host it once.

🖥 Admin console

The website staff use: Live Floor, POS, kitchen, bookings, customers, stock, marketing and settings. It opens in any browser, and each person sees only what their role allows.

⚙ Station agent

A Windows service on every gaming PC. It connects to the server, reports health, obeys signed commands, and locks the PC when time runs out.

🎮 Gaming Shell

The full-screen screen players see instead of the Windows desktop: lock screen, countdown, games, food ordering, help.

📱 Customer app

A phone web app (installable) for wallet, bookings, buying time, rewards, tournaments and inbox. Each venue has its own link.

📺 TV display & KDS

A TV screen next to a console shows its timer. The kitchen display shows food tickets. Both run in a browser.

2. How they connect

Browsers and phones talk to the server over HTTPS. Each gaming PC keeps one WebSocket connection open. The server signs every command, and the PC verifies the signature before doing anything.
The golden rule: the server owns the clock and the money. A PC can show a countdown, but only the server can start, extend or end time, set a price, or take a payment. Nothing typed on a gaming PC can grant free time.

What happens when you click "Start session"

Cashier clicks Start on PC-07→Server prices it & takes payment→Server saves the session with its end time→Server signs START_SESSION→Agent verifies the signature→Shell unlocks & shows the countdown

That whole trip takes under a second on a normal network. Every change streams back to every open Live Floor within about a second.

What if the internet drops?

  • The agent saved the session to disk, so the player keeps playing and the countdown keeps running.
  • If the server's "end" never arrives, the agent locks the PC by itself 20 seconds after the end time, so no free time is given.
  • Commands sent while a PC is offline wait on the server and are delivered when it reconnects, unless they've expired.
  • When the PC reconnects, it and the server compare notes. A stale session is ended, and a lost one is restarted.
  • Sessions that should have ended while the server itself was down are closed on its first check after restarting.

3. Organization, branches & plans

Platform→Organization (your company)→Brand (optional)→Branch (a venue)→Zone (a room/area)→Station (a PC, console, VR, sim)
  • Organization: your business. Customers, wallets, the menu, loyalty and staff are shared across all its branches.
  • Branch: one physical venue with its own timezone, tax, cash drawers, kitchen stations, warehouses and floor.
  • Zone: an area inside a branch, like Regular PCs, VIP, PS5 Lounge, VR Zone or Restaurant. Rates, game visibility and mass actions work per zone.
  • Station: anything you sell time on. PCs run the agent; consoles, VR and sims are "agentless".

Plans, modules and limits

Each organization is on a plan. The plan decides which of the 26 modules are switched on (for example Restaurant, Tournaments, CRM) and sets limits: branches, stations and staff accounts. The platform operator can override single modules for one organization. If a module is off, its pages and actions are refused, even through the API.

4. Staff, roles & permissions

Every staff member has their own login. What they can do comes from roles. A role is a bundle of permissions (111 in total), given to a person for a scope: the whole organization, one brand, or one branch. One person can hold several roles, for example Cashier at Dubai Marina plus Tournament Manager at Abu Dhabi.

You can also build custom roles. Nobody can grant a permission they don't have themselves.

Safety rules built in

  • Sensitive actions need a written reason: refunds, wallet adjustments, voids after cooking, stock waste, freezing a customer and similar (33 of them). The reason is stored in the audit log.
  • Separation of duties: technicians, kitchen staff and waiters can't touch wallets or refunds. A manager can't approve their own cash shift or their own purchase order.
  • Two-step sign-in (TOTP) by QR code, account lockout after 5 wrong passwords, and a 4-digit PIN for quick staff actions.
  • Tamper-evident audit log: each entry is chained to the previous one by a hash, so an edited or deleted entry is detected.

6. Stations & the Live Floor

Adding a PC (enrolment)

  1. Admin → Computers → Add stations. Pick the zone, how many PCs (1–500) and how long the code is valid (1–72 h). The code is shown once.
  2. On the PC, run ArenaOS-Station-Setup.exe and enter the code.
  3. The PC creates its own secret key, which never leaves the PC, and sends only the public half. The server gives it a name (PC-01, VIP-03 …) and the branch's command-checking key.
  4. Reinstalling Windows on the same PC re-enrols the same station, so its history is kept.

7. Pricing

A rate (pricing plan) belongs to the organization, a branch or a zone, and applies to a station class (PC, console, VR, simulator). When time is sold, the server picks the rate like this:

  1. The most specific wins: zone before branch before organization.
  2. It must match the station class, the customer's membership tier and the day and time window, in the branch's own timezone (so happy hours work).
  3. On a tie, the higher priority wins, then the cheaper one.
Way to sellExampleHow it's charged
MinutesAED 15 / hour, minimum 15 min, rounded to 5 minRate × time, paid up front
Package3 hours for AED 40 + 30 bonus minutesFixed price and duration
PassNight pass 00:00–06:00Ends at the window's end
Open (postpaid)"Pay when you leave"Charged on the time actually used, with grace and rounding
  • Membership discount (for example Gold −20 %) applies automatically. A staff discount needs the pos.discount permission.
  • Consoles: a rate includes N players (for example 2), and each extra controller adds a set price.
  • Promotions (happy hour, bonus minutes, codes) are added on top. See Promotions.
  • The price is locked in when the session starts. Editing a rate later never changes a running session.
  • All money is stored in whole minor units (fils, cents), so there are no rounding surprises.

8. Sessions, from start to finish

Three ways a session starts

At the desk

Cashier opens the station on the Live Floor, picks the customer (or walk-in guest), a duration or package, and payment: cash, card, wallet, prepaid time or pay later.

At the PC

A customer with prepaid time signs in on the Shell's lock screen with username + password or PIN. The session runs for their whole balance.

From a booking

Check-in (from 15 minutes before the start) starts a session on every booked station until the booking's end.

The server checks every timer every 2 seconds. Expiry is accurate to within about 2 seconds, even across restarts.

During the session

  • Extend: from the desk, or from the seat ("+ Add time", paid from the wallet). The end time moves and the PC is told.
  • Move: the customer changes PC. The old PC locks and the new one starts with the same end time and the same bill.
  • Food and prints ordered from the seat go on the same session bill. Everything is paid in one go.
  • The database refuses two live sessions on one PC, and every start, extend or sale is safe to retry: a double click never charges twice.

When it ends

  • Time runs out: the bill is finalised and the PC locks. For "pay later", the used time is charged now.
  • Customer logs out early: unused prepaid minutes go back to their time balance.
  • Staff end it: the same, from the drawer.
  • After the session the PC can lock, return to the lock screen, log out Windows, restart, shut down, or restore-reboot (set per branch). Games and launchers are closed so the next player never inherits someone's Steam login.
  • Loyalty points for the time and money are added when the bill settles.

9. The Gaming Shell (what players see)

When a standard Windows user signs in to a gaming PC, the agent starts the Shell full-screen. If it's closed or crashes, it's back within about 3 seconds. Administrator accounts get the normal desktop, which is how staff do maintenance. In safe mode the Shell doesn't start automatically.

🔒 Lock screen

Venue name, clock, station name, sign-in (username + PIN or password), English/Arabic, rates. Sign-in attempts are rate-limited.

⏱ Countdown

Ring and top-bar timer, warnings at 30/15/10/5/1 minutes, a pulsing last minute, a "Time's up" overlay, staff messages.

🎮 Games & apps

Search and categories, one tap to play, age ratings enforced. There are also approved apps (Discord, browser …) and platform launchers.

🍔 Order food

The menu, sent to the kitchen, paid on the session bill or from the wallet. Toasts show "preparing" and "ready".

🛠 Help & self-fix

"Call staff" by topic, plus safe fixes: flush DNS, restart audio, restart Shell. It also shows live ping, peripherals and mouse speed.

🖨 Printing

Each print job shows its price and waits for "Add to my bill" or "Pay from wallet" before it prints.

Why the Shell is safe

  • The Shell can't decide anything. It can only ask: "sign me in", "log me out", "launch game #12". The unlock only happens when a signed command from the server arrives.
  • It talks to the agent over a locked-down local pipe, and checks that the pipe really belongs to the Windows service.
  • The Shell page has no network access and can't navigate anywhere else. Pop-ups and downloads are blocked.
  • Games launch only if a session is running, the game is in the signed library, the customer is old enough and it's installed. Command prompts, PowerShell and similar tools never run.

10. Games, launchers & updates

  • Detection: each PC scans Steam, Epic and known install paths (Riot, Battle.net …) when it connects, every 30 minutes, and on demand. Admin → Games shows how many PCs have each title and how many need an update.
  • Library control: enable or disable titles, feature them on the home screen, limit them to zones (for example VIP-only), or add custom games. The list travels to PCs signed and is cached, so the library works offline.
  • Branch-wide updates: click Update and the server updates only PCs that need it, never one with a player on it (it waits until the session ends), a few at a time. PCs that were offline are retried when they come back.
  • Launch: Steam titles start with -applaunch <id>, and Epic through its launcher. The server never sends raw command lines.
  • Diskless: the agent detects diskless boot (iSCSI, CCBoot, ggRock …) and shows it on the drawer. Provider integration is on the Enterprise plan.

11. Consoles, VR, simulators & TV displays

Consoles, VR headsets and racing rigs run no ArenaOS software. The server's timer is the only clock. Otherwise they're sold exactly like PCs: same rates, packages, bookings, bills and wallet.

  • Players: a PS5 rate might include 2 players, with each extra controller adding a set amount per hour.
  • Minimum age: VR (13+) or a motion sim can refuse under-age customers. For guests, staff confirm the age.
  • Cleaning: VR stations go to Cleaning after each session and can't be sold until someone taps Mark cleaned.
  • Gear checks: controllers, headsets, wheels and pedals are tracked. A missing or faulty item raises an alert.

How the player knows time is up

  1. TV station display: open /display.html of the customer app on the TV's browser and pair it once with an 8-character code from Admin → Consoles & VR. It shows the player's first name, a countdown, warnings at 5 and 1 minutes, then "Time's up — hand back the controllers".
  2. Smart plug (optional, Shelly or Tasmota): one PC per branch acts as the bridge. It switches the console's power on when a session starts and off a moment after it ends. It will only ever talk to addresses on your local network.

12. Internet-café printing

Customer prints→Agent pauses the job→Server prices it (B/W or colour, per page)→Shell asks: bill or wallet?→Server charges & signs "release"→It prints
  • Nothing prints unpaid. A job un-paused by hand in Windows is paused again.
  • Optional staff approval per branch: the job waits in Admin → Printing until released. There's also a maximum page count.
  • Jobs not confirmed within 3 minutes, or not released within 15, are cancelled automatically. A failed print raises an alert so staff can refund.
  • Print control is off in safe mode.

14. Memberships

Tiers are sold (for example Silver AED 99 / 30 days, Gold AED 199) or earned (for example Legend). A tier sets:

  • discounts on gaming, restaurant and tournaments;
  • bonus minutes (added to the time balance on purchase);
  • how far ahead the customer can book, and priority booking;
  • a loyalty points multiplier.

Renewing the same tier adds the period on top. Switching tier ends the old one now. When a membership expires, the customer drops to their next active tier, or none. This is checked every minute.

15. Bookings

  • Book by zone (the first N free stations for N players) or pick specific stations. Duration 30 min to 12 h, up to 20 players.
  • Customers can book as far ahead as their tier allows (7 days by default); staff up to 60 days. The price is estimated from the rate that applies at the start time.
  • No double booking, ever: the database itself refuses overlapping bookings, even when requests arrive at the same instant. A walk-in session can't be sold into an upcoming booking, and staff see how many minutes are still free.
  • Check-in opens 15 minutes before the start, and payment can be cash, card, wallet, prepaid time or pay later.
  • Automatic: 15 minutes late marks it a no-show and releases the stations. Customers can cancel in the app up to 60 minutes before; staff can cancel any time, with a reason.

18. Shifts & the cash drawer

  1. Open a shift on a drawer with the opening float. There's one open shift per drawer and one per cashier per branch. Cash can't be taken without an open shift; card and wallet can.
  2. During the shift, record pay-ins, pay-outs and safe drops (with reasons). Cash sales, change and cash refunds are recorded automatically.
  3. The X-report (any time) shows sales by method, refunds, movements and expected cash.
  4. Close: count the cash and enter it. The difference is stored. Above the branch threshold (default 5.00) the shift goes to Pending approval, and another manager must approve it.
  5. The Z-report totals are frozen on the closed shift.

19. Restaurant, tables & kitchen display

  • Menu: categories, products, option groups (extras, size, milk …), per-branch prices, and sold out / "86". Each product has a kitchen station (Kitchen, Bar …).
  • Tables: ordering at a table marks it Occupied. Settling its bill sets it to Cleaning, and staff mark it free.
  • Kitchen display: each order makes one ticket per station. Tickets go through columns New → Cooking → Ready → Served, with timers, and turn red after 12 minutes. New tickets chime, and the screen updates live.
  • In-seat orders: when the kitchen starts or finishes an order from a PC, that player's Shell shows "preparing" and "ready".

20. Inventory & purchasing

  • Warehouses per branch (main store, kitchen, bar, tech store), plus an optional central warehouse. Items are counted in a base unit (pcs, g, ml) and bought in cases.
  • Sales deduct stock automatically: a can deducts 1 can; a burger deducts its recipe (bun, patty, sauce + planned waste %); an "extra patty" option deducts its ingredient. Bar items come from the bar store, kitchen items from the kitchen store.
  • A miscount never blocks the till: stock may go negative and raises an alert. Manual moves (waste, issue to a PC, transfers) can't go below zero.
  • Batches & expiry (used earliest-expiry first) and serial numbers for headsets, controllers and PC parts.
  • Cost: a moving average updated on each delivery. The menu shows the food-cost % and margin per item.
  • Counts, waste and transfers with reasons, all audited.

Purchasing

Draft PO→Submit→Approve (if over the limit, by someone else)→Ordered→Receive (partial or full)→Supplier invoice matched

Reorder suggests what to buy for each store (items at or under their minimum, minus what's already on order) and drafts one PO per supplier in one click. You can never receive more than ordered, and invoice payments can never exceed the invoice.

22. Promotions

A promotion is conditions → effects, with limits.

Conditions

  • Days and hours (happy hour)
  • Branches and zones
  • Tiers and segments
  • Minimum spend, product categories
  • First visit, birthday week

Effects

  • % or amount off time, food or everything
  • Bonus minutes
  • A free product

How the discount is chosen: take every automatic promotion that applies plus the entered code. Keep the single best non-stackable one, add every stackable one, and cap the total at the price. Budgets and limits hold even when two tills redeem at the same moment.

23. Tournaments

  1. Create: the game and a format. Formats are single elimination, double elimination (with grand final), round robin, league and Swiss. Also set team size, entry fee and prizes.
  2. Registration: teams join at the desk or in the app. A player can't be in two teams. The entry fee goes through the POS or the wallet.
  3. Start: close entries, check in, seed (byes go to top seeds) and build matches. Stations can be assigned to matches.
  4. Play: staff report scores and winners advance automatically. Swiss rounds pair themselves from the standings.
  5. Finish: placements are computed, prizes can be paid to the captain's wallet, and every player earns points. Withdrawing or cancelling refunds entry fees.

24. CRM & campaigns

  • Segments: built-in (New, Regular, VIP, Inactive, High spender, Competitive, Restaurant-heavy, Gaming-heavy), custom rules (visits, minutes, spend, recency, age, tier), or hand-picked lists.
  • Campaigns: one segment and one channel: in-app inbox, a Shell message at the customer's next session, or SMS / email / WhatsApp. Messages can include {{firstName}}, {{points}} and {{code}}, and each recipient can get their own promo code.
  • Consent only: only customers who opted in receive campaigns. Sending again only reaches new members of the segment.
  • Results: delivered, read, and converted (codes redeemed).

25. Security & your data

Tenants kept apart

Three independent layers keep one organization's data from another's: database row-level security, a tenant-scoped data layer, and permission checks on every request. Each layer is tested.

Signed commands

Each branch has its own signing key. PCs only hold the public half, so a hacked PC can't forge "unlock". Old commands can't be replayed, and each is bound to one PC.

PC identity

Each PC's key is encrypted to that machine. Connecting requires fresh proof it holds the key. Retiring a PC cuts it off instantly.

Staff logins

Short-lived tokens kept in secure cookies (never visible to page scripts), refresh rotation with theft detection, two-step sign-in, lockout.

Money ledgers

Wallet, points and stock movements can only be added, never edited. Balances can't go negative. Every write is safe to retry.

Audit trail

Every sensitive action and every denied attempt is logged with who, what and why, in a hash chain that exposes tampering.

Your job as the host: use strong passwords, keep the database private, back up the database and the .env file (it holds the signing keys), and keep the server updated.

26. A day at the venue

🌅 Opening

  • Cashier signs in and opens a shift with the float.
  • Check the Live Floor: all green? Wake any offline PCs.
  • Clear overnight alerts (temperatures, missing peripherals).
  • Look at today's bookings and tournaments.
  • Kitchen: open the Kitchen display; check sold-out items.

🎮 During the day

  • Sell time at the desk, or players sign in with prepaid time.
  • Watch orange tiles (ending soon) and offer extensions.
  • Answer 🔔 help requests; run repairs from the drawer.
  • Check in bookings from 15 minutes before; no-shows release automatically.
  • Kitchen bumps tickets; players get "ready" on their PC.
  • Run game updates. They wait for idle PCs by themselves.

🌙 Closing

  • End remaining sessions (prepaid time is refunded automatically).
  • Settle open bills and tables.
  • Print the X-report, count cash, close the shift. A manager approves any variance.
  • Record waste; run Reorder for tomorrow's purchase orders.
