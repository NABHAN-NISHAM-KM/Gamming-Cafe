## 2. Bugs

### QA-01: Two concurrent payments on one bill both capture (Critical)
- **Where:** `payBill` in [orders.service.ts:293](../apps/api/src/pos/orders.service.ts) reads the bill and computes `due` without a row lock (`SELECT … FOR UPDATE`) or a version check.
- **Steps:**
  1. Cashier creates an unpaid order for a cola (8.00 AED).
  2. Send two `POST /bills/:id/pay` requests at the same moment, each with its own idempotency key. This is what two tills, or a double-click before the first response, would do.
- **Expected:** one 200; the other gets 409 `already_paid`.
- **Actual:** both return 200. Bill DXB1-261006-4EC5FE has two CAPTURED CARD payments of 8.00, but `paidTotal` shows 8.00. The sales report's card total includes both.
- **Fix:** lock the bill row at the top of `payBill`. The same lock-free read pattern is worth checking in the session `extend` and wallet paths.

### QA-02: A partial refund reopens a settled bill and erases its revenue (High)
- **Steps:**
  1. Settle bill DXB1-261006-728299 (79.00 AED: gaming time + F&B, paid from the wallet).
  2. Manager refunds 10.00 of the F&B payment to the wallet.
- **Expected:** the bill stays SETTLED, and the refund shows as a refund.
- **Actual:**
  - The bill goes to PARTIALLY_PAID, `closedAt` is cleared, and it shows **10.00 due**. Staff would be prompted to collect the refunded money again.
  - The sales report and dashboard count SETTLED bills only, so the bill's full 76.57 net disappears. Today's revenue drops from 76.57 to 20.00 AED.
  - The P&L (correctly) shows 86.88 AED.

### QA-03: Gaming time is billed with no VAT (High: tax compliance)
- **Where:** `addCharge` in [sessions.service.ts:575](../apps/api/src/sessions/sessions.service.ts) creates the gaming order and item without `taxTotal` or `taxAmount`. The branch tax profile is "UAE VAT 5%, applies to ALL".
- **Actual:** `/reports/vat` lists 28.00 AED of gaming as "No VAT (exempt / zero-rated)". Output VAT is understated by 5/105 of all gaming revenue (1.33 AED on this test). The ledger books no VAT liability for gaming, and refunds take VAT pro-rata over a bill whose gaming part has no tax.
- **Expected:** gaming lines pick up VAT from the tax profile, the same way F&B does (`appliesTo: GAMING` or `ALL`).

### QA-04: Malformed IDs return 500 instead of 400/404 (Medium)
- **Steps:** `GET /customers/abc`, `/bills/abc`, `/bookings/abc`, `/orders/abc`, `/shifts/abc`, `/tournaments/abc`, or `/customers/1' OR 1=1--`.
- **Actual:** 500 `internal_error`, with a stack trace in the server log. `/sessions/abc` and `/devices/abc/session` correctly return 404.
- **Impact:** no data leaks, and it isn't SQL injection (queries are parameterized). But every bad link or bot probe logs an error and counts toward the 5xx rate.
- **Fix:** a global UUID param pipe, or map Prisma's invalid-UUID error to 404.

### QA-05: Dashboard "top spenders" counts wallet money twice (Medium)
- **Where:** [analytics.service.ts:131](../apps/api/src/reports/analytics.service.ts) sums every SETTLED bill's total, including the top-up bill and bills paid from the wallet.
- **Actual:** the QA customer paid in 100.00 AED but shows **179.00** spent.
- **Expected:** `docs/11` §Spend says wallet payments are left out because the top-up was already counted. `Customer.totalSpend` follows that rule; this query doesn't.

### QA-06: Ending a money-paid session early refunds nothing (Medium: confirm intent)
- **Steps:**
  1. Start a 97-minute session paid from the wallet (24.25 AED).
  2. Extend it by 15 minutes (3.75 AED).
  3. End it after 4 minutes.
- **Actual:** the full 28.00 AED is kept. Only sessions paid from the **time balance** get unused minutes back ([sessions.service.ts:439](../apps/api/src/sessions/sessions.service.ts)).
- **Question:** `docs/09` says "unused prepaid minutes refunded to the balance". Either refund wallet-paid sessions too, or make the doc and the staff "End" dialog say plainly that money-paid time isn't refunded.

### QA-07: No security headers anywhere in the repo (Medium)
- **Actual:** admin, API and website send no HSTS, `nosniff`, `X-Frame-Options` or CSP. `docs/23` hands this to Nginx, but there's no Nginx config in the repo and the API doesn't use `helmet`.
- **Fix:** ship a reference `infra/nginx.conf`, or set the headers in the apps so a missed proxy step doesn't leave them off.

### QA-08: Off-peak → peak sessions aren't split (Low: by design)
- **Where:** the rate card is picked once, at start (`selectPlans(ctx.now)`), and a prepaid session is paid in full up front.
- **Effect:** a session that starts in happy hour keeps happy-hour pricing for its whole length. That's probably intended, but cross-check 2 of the QA prompt can't pass. Document it.

### QA-09: "Takings" isn't money received (Low)
- **Actual:** dashboard and sales "takings" add top-up bills and wallet-paid bills together. Today it showed 279.00 AED, while only 207.50 AED actually came in.
- **Fix:** rename it, or exclude wallet-paid bills.

## 4. Security and tenancy (passed)

- **Tenancy:** Rival Gaming's owner gets 404 on every Demo Arena ID tried: customer, wallet, top-up, floor, session, ending a session, bill, pricing plan, order. A customer search returns `[]`.
- **RBAC:** the cashier is refused pricing changes, financial reports, accounting, wallet adjustment, export and refunds (403). The technician can't start sessions or see customers. The accountant can't start sessions. DXB1 staff are refused on AUH1 (`OUT_OF_SCOPE`). Approving your own shift is refused, and a manager's approval needs a reason.
- **Auth:**
  - Unknown email and wrong password give the same error.
  - Missing or forged tokens get 401.
  - Replaying a refresh token kills the rotated session.
  - Super Admin always requires two-step.
  - A venue token is refused by the platform service.
  - Player sign-in is throttled (8 attempts per account, 20 per IP, per 15 minutes).
- **Idempotency:** replaying a session start, extend or order with the same key returns the original and charges once. Two staff starting one PC: one 201, one 409. A three-way race for one booking slot: one winner. Overlapping bookings are refused; back-to-back ones are allowed.
- **Payments:** forged Stripe webhooks get 403 `bad_signature` on both the venue and platform services. The check is timing-safe HMAC with a 5-minute replay window, plus amount and currency matching.
- **Input:**
  - `<img src=x onerror=alert(1)>` saved as a display name renders as text in the admin console.
  - `' OR 1=1 --` is refused by the username validation.
  - Negative tenders are refused, as are refunds above the refundable amount.
- **Files and CORS:** `.env`, `.git/config` and `package.json` are not served by admin or website. The API doesn't echo back a hostile CORS origin.
